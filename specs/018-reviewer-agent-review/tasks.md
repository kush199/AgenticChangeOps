# Tasks: Reviewer Agent Reviews A Change Proposal

**Input**: Design documents from `specs/018-reviewer-agent-review/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (record-and-audit, system-check-rules, reference-and-limit-rules, settings-and-failures, http-api-unchanged), quickstart.md

**Tests**: Included and written first, **per delivery step** (Constitution Principle VI and the project's test-approval checkpoint). Each step adds its new types as compiling **stubs**, writes its tests, shows them red once, waits for the word "approved", then implements until green. Because the spec requires every step to leave all tests passing (FR-021), no red test is ever carried from one step into the next, and no step is committed while red.

**Constitution**: [x] Reviewed against constitution v1.0.6 before approval (see plan.md Constitution Check and compliance table). Tick at T001.

**Organization**: Grouped by delivery step, which is how the spec asks the work to be split (FR-021). Each task carries the user story it serves from spec.md: US1 produce a verified advisory review (P1), US2 retrieve latest and history (P1), US3 refusals store nothing (P1), US4 bad or failed review rejected whole (P1), US5 sample check degrades gracefully and stale inputs refused (P2), US6 nothing else changes (P2). Step 1 is pure logic that nothing calls; step 2 adds the model-facing pieces; step 3 the service, store and audit; step 4 the registration; step 5 polish.

**Rules that hold for every task**:
- With the Reviewer unused every existing response, status code, body and header is byte-identical and every existing test passes **with no assertion edited** (FR-020). Existing test files only gain new files beside them. The only edits to existing test data allowed are those listed in `baseline/expected-test-edits.md`, approved by the user at T004 (tests that enumerate every `AuditEventType` value, additions only). If any other existing test fails, fix the new code, never the assertion.
- Nothing is written, created, deleted, compiled or run anywhere by this feature. The only file reads are the system's own re-check of the sample, by the adapter, read-only (FR-010).
- Nothing in any error, log, response or audit entry carries model text, a finding statement, file content, a quote, a path, an endpoint, a deployment name or a credential (FR-018). Rejections return the reason code only.
- `AgenticChangeOps.Agents.Reviewer` references only Drafting, Intake and ModelAccess. It names no other agent and not `AgenticChangeOps.SampleCode`. It must not contain `CancellationTokenSource`, `JsonDocument`, `GetProperty(`, `IsNullOrWhiteSpace(` or code fences (the shared-behaviour guard scans every `Agents.*` folder), and it does not re-implement the order of steps (it uses `DraftingEngine`).
- The model never decides eligibility, a reference outcome, a limit, a status or any decision (Principle II); severity and category are labels nothing reads. No live model call in the suite; scripted fakes only.
- Synthetic data only (Principle I); hostile text is generated filler with a made-up marker such as `HOSTILE-MARKER-0001`.
- After every code task `dotnet build AgenticChangeOps.sln` succeeds. At the end of every step `dotnet test AgenticChangeOps.sln` is green.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: parallel (different files, no dependency on an incomplete task). Tasks editing the same file are never `[P]`.
- **[Story]**: US1 to US6, from spec.md (setup and polish tasks carry none).
- **[USER]**: outward-facing step (push, PR) or a human gate. Claude drafts, the user confirms.
