# Tasks: A Person Accepts Or Rejects A Design Draft

**Input**: Design documents from `specs/022-design-acceptance-decision/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/http-api.md, quickstart.md

**Tests**: Included and written first (Constitution Principle VI and the project's test-approval checkpoint). Tests are written with compiling stubs, shown red once, and implementation starts only after the user says "approved".

**Constitution**: [x] Reviewed against constitution v1.0.6 (plan.md Constitution Check and the table at the end of this file). Tick at T001.

**Organization**: Grouped by the user stories in spec.md: US1 accept the latest design (P1), US2 reject with a reason (P1), US3 decisions are final, current and exclusive (P1), US4 invalid requests are refused without side effects (P2), US5 audit and nothing else moves (P2). One small slice, so a single delivery step. The decision record, service and route are shared by all stories, so they are built once in Phase 3 and each story phase proves its own behaviour.

**Rules that hold for every task**:
- Every existing response, status code, body, header and error code is identical, except the additions in `contracts/http-api.md` (one new operation, one optional `decision` member on the two design GETs, one new audit event type). Every existing test passes with its assertions unchanged, except those listed in `specs/022-design-acceptance-decision/baseline/expected-test-edits.md`, approved at T003. If any other test fails, fix the new code, never the assertion.
- A decision never updates the change request (no `Update*` call), never starts a step, and is never invoked by Workflow, the advancement host or any agent. Records are never edited or deleted.
- Nothing in any response, log or error carries model text, file content, a path, an endpoint, a deployment name, a credential, or the caller's decision value. Refusals store nothing (no decision, no audit entry).
- No change to Workflow, proposals, reviews, automatic advancement, the SQLite schema or the approval decision classes. Synthetic data only. No live model call in the suite.
- After every code task `dotnet build AgenticChangeOps.sln` succeeds; at the end `dotnet test AgenticChangeOps.sln` is green.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: parallel (different files, no dependency on an incomplete task).
- **[USER]**: outward-facing step (push, PR) or human gate. Claude drafts, the user confirms.
