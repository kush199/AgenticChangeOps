# Tasks: Fix Three Rough Edges From Manual Testing

**Input**: Design documents from `specs/014-fix-rough-edges/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/response-changes.md, quickstart.md

**Tests**: Included and written first (Constitution Principle VI and the project's test-approval checkpoint). Nothing in this slice adds a type or member, so there are no stubs: new and changed tests are run against the **unchanged** code and must fail for the right reason (the old message, the old 409/stop, the old 503), then be approved at T014 before any source file changes.

**Constitution**: [x] Reviewed against constitution v1.0.4 before approval (see plan.md Constitution Check). Tick at T001.

**Organization**: Grouped by user story (US1 messages, US2 Approved draft, US3 check order). The stories touch different source files and are independent. All tests are written together (Phase 2) and shown red once; each story's implementation then turns its own tests green (Phases 3 to 5).

**Rules that hold for every task**:
- Permitted production edits are exactly the six files named in plan.md "Source Code": `src/AgenticChangeOps.Intake/Services/ChangeRequestValidator.cs`, `src/AgenticChangeOps.Intake/Services/ApprovalDecisionValidator.cs`, `src/AgenticChangeOps.Agents.Requirement/RequirementsDraftingService.cs`, `src/AgenticChangeOps.Workflow/WorkflowRules.cs`, `src/AgenticChangeOps.Api/Endpoints/DraftEndpoints.cs`, `src/AgenticChangeOps.Api/Endpoints/DesignEndpoints.cs`. No new file in `src/`, no new type, member, setting, package, operation or route. `ApprovalDecisionValidator` changes only its decision message (`ValidateStatus` and every other rule stay). `WorkflowReasonCode.RequirementsDraftRequired` stays in the enum, unused. `ErrorMapper`, the services' other code, the Architect agent, `ApprovalService` and `WorkflowService` are not edited.
- **Existing-test edits are limited to this list, each flagged for approval at T014** (all are listed in plan.md "Tests that assert a changed response"): `tests/AgenticChangeOps.Api.Tests/DraftEndpointTests.cs` (`Draft_OnApprovedRequest_Returns409WithSpecificReasonAndGeneratorNotCalled`); `tests/AgenticChangeOps.Agents.Requirement.Tests/Unit/DraftEligibilityTests.cs` (the `Approved` rows of the two theories and `Draft_RequestBecomesApprovedDuringGeneration_IsRefusedAndConsumesNoVersion`); `tests/AgenticChangeOps.Agents.Requirement.Tests/Unit/DraftingFailureCategoryTests.cs` (`EligibilityFailure_CategoryIsNull`); `tests/AgenticChangeOps.Workflow.Tests/Unit/WorkflowRulesTests.cs` (`Row7_…`); `tests/AgenticChangeOps.Workflow.Tests/Unit/AdvanceRefusalTests.cs` (`ApprovedWithoutRequirementsDraft_NeedsOne`); `tests/AgenticChangeOps.Workflow.Tests/Automatic/FailureWaitTests.cs` (`AFailureWithNoCategory_BecauseTheFactsChangedMidStep_IsNotCounted`: the mid-step change is now a rejection, not an approval; added after T022 with the user's approval); `tests/AgenticChangeOps.Api.Tests/DesignFailureTests.cs` (`Parity_StateRefusalHasTheSameStatusCodeAndCodeAsRequirementsDrafting`: the approved request first receives its requirements draft; same approval); and the golden `tests/AgenticChangeOps.Api.Tests/Baseline/golden/transcript.txt` (only the lines the plan lists). No other existing assertion is touched. If any other existing test fails, fix the new code, never the assertion. `RequirementsEligibilityDriftTests` must pass unchanged.
- No response, log line or error carries caller text, model text, an endpoint, a deployment name or a credential (FR-009). Validation errors never see the caller's text: the API maps it to the out-of-range value first.
- The model is never asked what is due or whether a transition happens (Principle II). No task adds a model call; no test calls a live model.
- Synthetic data only (Principle I): use `SyntheticData` and the existing fixtures; hostile and long text are generated filler (for example `new string('x', 5000)` and a made-up marker such as `HOSTILE-MARKER-0001`).
- After every task that touches code, `dotnet build AgenticChangeOps.sln` succeeds; after every phase from Phase 3 on, `dotnet test AgenticChangeOps.sln` is green (except the deliberately red state at T013).

- **[Story]**: US1 to US3, from spec.md.
