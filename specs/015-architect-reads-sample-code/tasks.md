# Tasks: Architect Consults A Sample Codebase

**Input**: Design documents from `specs/015-architect-reads-sample-code/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/ (tools, settings-and-failures, audit-and-record, http-api-unchanged), quickstart.md

**Tests**: Included and written first (Constitution Principle VI and the project's test-approval checkpoint). New types and members are added as compiling **stubs** (Phase 2) so the new tests fail for the right reason (not-implemented behaviour, not a compile error); all new tests are shown red once and approved at T032 before any behaviour is implemented.

**Constitution**: [x] Reviewed against constitution v1.0.4 before approval (see plan.md Constitution Check; the v1.0.5 amendment is a separate PR). Tick at T001.

**Organization**: Grouped by user story from spec.md: US1 design cites real files (P1), US2 tools off changes nothing (P1), US3 confinement and limits (P2), US4 failing safely (P2), US5 hostile content stays data (P2). Foundational code (settings, confinement, reader, budget, session, MCP server) is shared and is built in Phase 4 under US3's tests, because US1 needs it; see Dependencies.

**Rules that hold for every task**:
- Tools off is the default and must be byte-identical to today (FR-011). **No existing test assertion is edited, with one user-approved exception (decided at T006, 2026-10-17):** appending `ToolsUnavailable` and `LimitsExhausted` to `GenerationFailureCategory` breaks tests that list every member, so exactly these are edited, additively, and shown for approval at T032: the expected member list in `tests/AgenticChangeOps.Agents.Requirement.Tests/MovedTypeShapeTests.cs` (`GenerationFailureCategory_KeepsItsMembersAndValues`), and the golden files `tests/AgenticChangeOps.Api.Tests/Baseline/golden/transcript.txt` and `shared-plumbing-transcript.txt`, which gain only the lines for the two new values (the old lines differ only by renumbered `<id-N>` placeholders), and `openapi.json`, which gains the two category values, the new `ToolCalled` audit event value, and the new nullable audit and design members (all regenerated with `ApiBaselineTests.UpdateVariable`, diffs reviewed to be additions and renumbering only). If any other existing test fails, fix the new code, never the assertion. Existing fakes (`FakeChatModelClient`, `FakeDesignGenerator`, `FakeRequirementsBasisSource`) must compile unchanged. Existing test files may only gain new test files beside them, never edits, except adding the new project to the solution.
- Read-only: no code path opens anything under the sample for writing, runs it, deletes it, or reaches a network (FR-006). The MCP pair is in-process memory pipes only.
- Nothing in any error, log, response or audit entry carries file content, model text, an endpoint, a deployment name, a credential, or a filesystem path outside the sample (FR-020). Refusal text is the fixed text in contracts/tools.md.
- Framework and MCP types appear only in `AgenticChangeOps.SampleCode` and `AgenticChangeOps.ModelAccess`. The Architect project still references only Intake and ModelAccess (existing `StructureTests` must pass unchanged).
- The model is never asked what is due, whether a transition happens, or whether something is approved (Principle II). No live model call in the test suite; scripted fakes only.
- Synthetic data only (Principle I): the sample and every fixture are invented; hostile text is generated filler with a made-up marker such as `HOSTILE-MARKER-0001`.
- After every task that touches code, `dotnet build AgenticChangeOps.sln` succeeds. After every phase from Phase 4 on, `dotnet test AgenticChangeOps.sln` is green (except the deliberately red state at T031).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task). Tasks editing the same file are never `[P]`.
- **[Story]**: US1 to US5, from spec.md.
- **[USER]**: outward-facing step (push, PR, amendment PR). Claude drafts, the user confirms.
