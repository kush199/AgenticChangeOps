# Tasks: Automatic Advancement of Change Requests

**Input**: Design documents from `specs/013-automatic-advancement/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included and written first (Constitution Principle VI and the project's test-approval checkpoint). New tests are shown red against signature-only stubs whose members throw `NotImplementedException`, and approved (T034) before any stub is filled in. Red means failing for the right reason: behaviour, not missing types.

**Constitution**: [x] Reviewed against constitution v1.0.4 before approval (see plan.md Constitution Check; the non-consequential classification of the two draft steps is the item to confirm).

**Organization**: Grouped by user story (US1 to US5 from spec.md). The new store members, settings type, runner interface and the check service are shared by all stories, so their stubs are Foundational; all story tests are written together (Phase 3) and shown red; each story's implementation then turns its tests green (Phases 4 to 8).

**Rules that hold for every task**:
- Permitted production edits are exactly the files named in plan.md "Source Code": `src/AgenticChangeOps.Intake/` (`Models/ChangeRequestAuditEntry.cs`, new `Models/AutomaticAttempt.cs`, `Stores/IChangeRequestStore.cs`, `Stores/InMemoryChangeRequestStore.cs`), the two agent drafting services and their interfaces (`automatic` parameter and audit stamp only), `src/AgenticChangeOps.Workflow/` (new files, `WorkflowStatus.cs`, `AdvanceOutcome.cs`, `WorkflowService.cs`), `src/AgenticChangeOps.Persistence/` (`StorageSchema.cs`, `SqliteChangeRequestStore.cs`), `src/AgenticChangeOps.Api/` (`Composition/ApiServiceRegistration.cs`, new `Composition/AutomaticAdvancementHostedService.cs`, new `Endpoints/OperatorEndpoints.cs`, `Program.cs` only to map the new endpoint), `README.md`. Nothing else in `src` changes: no change to `WorkflowRules.cs`, to how any agent builds content, to any existing endpoint, to any approval path, or to any existing member of a public type.
- **Existing-test edits are limited to these three, each needed and each flagged for approval at T034**: (a) `tests/AgenticChangeOps.Persistence.Tests/Durable/LayoutVersionTests.cs`: the test `ANewFile_IsStampedWithLayoutVersionOne` now expects version 2 (rename it `ANewFile_IsStampedWithCurrentLayoutVersion`); (b) `tests/AgenticChangeOps.Api.Tests/Storage/StorageErrorTests.cs`: `ThrowingStore` gains the four new interface members (each throwing the stored exception), nothing else; (c) `tests/AgenticChangeOps.Persistence.Tests/Contract/ChangeRequestStoreContract.cs`: new cases C14 and later are added, no existing case changes. No other existing assertion is touched. If any other existing test fails, fix the new code, never the assertion.
- Workflow stays a non-web project: it must not name `Microsoft.AspNetCore`, `HttpContext`, any model client, or a generator interface (existing structure rule 5), must not build drafts or audit entries, and must not call `SaveAgentOutput`, `SaveDraft(`, `SaveDesign(`, `RecordDecision`, or `Store.Update` (existing rules 6 and 7). Its only store writes are `SaveAutomaticAttempt` and `ClearAutomaticAttempt` (attempt bookkeeping, not records of the change request); `WorkflowRules.cs` is untouched and keeps passing rule 8. Logging is done by the Api hosted service from the returned `CheckSummary`, so Workflow takes no logging package.
- No summary, status, audit entry, log line or error carries model text, an endpoint, a deployment name, a credential, a path or a driver message (FR-020). Failure details are the existing category only.
- The model is never asked what to run, in what order, or whether to stop (Principle II). No task adds a model call.
- Synthetic data only (Principle I). Temp database files live under the test run's temp folder and are deleted after each test.
- After every task that touches code, `dotnet build AgenticChangeOps.sln` succeeds; after every phase, `dotnet test AgenticChangeOps.sln` is green (except the deliberately red state at T033).
- Layout version for this slice is `2` (a version-1 file is upgraded in place).
- Record comparison in tests is member-wise (`SequenceEqual` for list members), never plain record equality on records holding lists.
- Time in tests comes from a fake `ISystemClock`; no test sleeps, waits on a real timer, or calls a live model.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on an incomplete task). Tasks editing the same file are never `[P]`.
- **[Story]**: US1 to US5, from spec.md.
- **[USER]**: outward-facing step (push, PR). Claude drafts, the user confirms.
